Dates follow Obsidian and the site's locale (bases-page#8). Date values show as Obsidian shows them, moment's `L` for dates and `L LT` for datetimes, in Quartz's `configuration.locale` (`03/05/2024 2:30 PM` for en-US, `05.03.2024 14:30` for de-DE, `2024/03/05` for zh-CN), instead of JSON such as `"2024-03-05T00:00:00.000Z"`; date properties (`due: 2024-03-05`) display the same way. `.format()` uses the locale's month and day names and supports moment's `L`, `LL`, `LLL`, `LT`, `Do`, `dddd`, `[escaped]` and the other common tokens; `.relative()` gives moment's `3 years ago` / `vor 3 Jahren`. On date properties `.year`, `.month`, `.format()`, `.relative()`, `.date()`, `.time()` and comparisons with dates work. **Changed, as in Obsidian:** `date()` reads only ISO-style strings (`2024-03-05`, `2024-03-05 14:30`, `2024-03-05T14:30:00Z`) and `20240305`, in local time; other strings (`05/03/2024`, `March 5, 2024`, `2024/03/05`) give an empty value instead of a guess by the JavaScript `Date` parser, which read `05/03/2024` as May 3. `date(<number>)` is an error, and `.date()` returns a date (shown as a date) rather than text.
